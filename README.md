# FlightLab

Браузерный анализатор Blackbox-логов **Betaflight**. Загрузка `.bbl` / `.bfl` / CSV,
выбор полёта и интервала, Gyro / Setpoint, P / D-term, Welch-спектр и объяснимые
рекомендации. Цель управления, полезная нагрузка и масса задаются для каждого борта.

## Запуск

Нужен Node.js >=22.12 (проверено на 24.19) и npm.

```sh
cd /workspace/test
npm ci
npm run dev
```

Для сборки: `npm run build`. Для проверки сборки: `npm run preview`.
Это статическое приложение: содержимое `dist/` можно разместить на HTTPS-хостинге.
Для GitHub Pages подготовлена отдельная самодостаточная сборка и автопубликация.
Для разработки используйте текущий checkout; отдельный worktree не требуется.

### GitHub Pages

В репозитории `bogdanshevchenko838-web/test` выберите **Settings → Pages →
Build and deployment → Deploy from a branch → gh-pages → / (root) → Save**.
Это включает сам сайт; публикация облачной среды для этого не нужна.

Workflow `.github/workflows/deploy-pages.yml` при обновлении `main` запускает
тесты, собирает самодостаточный HTML и обновляет ветку `gh-pages`.
Ручной запуск доступен через Actions → Deploy FlightLab to GitHub Pages → Run workflow.

Локальная команда `npm run build:pages` (Node.js и Python 3) создаёт `dist-offline/`
с `.nojekyll`, лицензией и `corresponding-source.zip`. Публикуется только эта папка:
локальные логи, `.env`, профили браузера и `node_modules` в сайт не попадают.
У Pages остаются ограничения тарифного плана GitHub и настроек Actions.

### Открытие без сервера

`npm run build:offline` создаёт **один файл** `dist-offline/index.html`:
JavaScript, Worker, стили и шрифты включены внутрь. Скачайте файл, переименуйте
в `FlightLab.html` и откройте в Chrome/Edge двойным щелчком. Встроенный просмотр
HTML внутри чата может не выполнять JavaScript — файл нужно открыть браузером.
Node.js и сервер на компьютере пользователя не требуются. Этот файл можно
передать другим пилотам; публичный веб-адрес появится после размещения на хостинге.
Проверка самодостаточности сборки: `npm run test:offline` (все запросы зависимостей
заблокированы). В управляемом браузере этой облачной среды `file://` запрещён
администратором, поэтому прямая навигация двойным щелчком в нём не проверена.

## Проверки

```sh
npm test
npm run test:browser
npm run build
```

Браузерные тесты используют системный `/usr/bin/chromium`, если он есть.
Иначе установите браузер Playwright: `npx playwright install chromium`.
Другой исполняемый файл можно задать через `CHROMIUM_PATH`.
Playwright сам запускает dev-сервер; локальный уже запущенный сервер переиспользуется.

## Работа с инструментом

1. Укажите название борта, цель (плавно / баланс / резко), груз и известную массу.
   Размер — диаметр винтов. Взлётная масса включает аккумулятор и груз.
2. Загрузите лог или откройте явно обозначенный синтетический демопример.
3. По желанию загрузите текст `diff all` либо `dump all`. Отметьте, что он относится
   к тому же борту и активному PID-профилю. При смене файла или профиля конфигурация
   сбрасывается; при смене полёта подтверждение снимается.
4. Выберите участок, ось и тип графика. Отчёт разделяет измерения, рекомендации
   по выявленным симптомам и предпочтения пилота.
5. Экспортируйте JSON-отчёт с метриками, настройками, методикой и ссылками.

`diff all` не содержит неизменённые значения. Если нужного параметра нет,
инструмент не подставляет дефолт: загрузите `dump all` или добавьте результаты
`get` нужных параметров в формате `set имя = значение`.

### CSV

Поддерживаются запятая, точка с запятой и табуляция, кавычки и строки метаданных
перед заголовком. Нужны `time` и минимум одна ось `gyroADC[0]`…`gyroADC[2]`.
`time` без суффикса означает микросекунды; поддержаны `(us)`, `(ms)` и `(s)`.
Предпочтительно явно указывать `gyroADC[0] (deg/s)` и `setpoint[0] (deg/s)`.
Для сырого экспорта Blackbox Explorer поддержаны `gyroScale` (rad/µs на единицу)
и `blackbox_high_resolution`. Без подтверждённой шкалы CSV остаётся описательным
анализом; численные кандидаты отключены. `rcCommand` не заменяет setpoint.

Лимиты: 128 МиБ, суммарно до 1 000 000 кадров, до 100 полётов. Испорченные полёты
перечисляются в предупреждениях; файл не обрезается молча при превышении лимита.

## Несколько пользователей

Любой пользователь может открыть одну и ту же развёрнутую статическую версию.
Аккаунт и сервер анализа не требуются. Логи обрабатываются Web Worker в памяти
его браузера и не отправляются на сервер. Шрифты включены в сборку; аналитики
и внешних запросов во время анализа нет. Ссылки на документацию открываются
только по действию пользователя.

До 20 профилей хранятся в localStorage **этого браузера и origin**. CLI и логи
не сохраняются. Два пользователя в разных браузерах имеют независимые данные;
на общем устройстве в одном профиле браузера сохранённые борта общие. Серверной
регистрации, синхронизации, командной библиотеки и разграничения аккаунтов нет.

## Возможности и границы рекомендаций

* Измерение частот и ошибок — математическое. Диагностические пороги — собственные
  инженерные эвристики; они ещё не откалиброваны на размеченном наборе реальных полётов.
* Пробное снижение `dterm_lpf1_dyn_min_hz` на 10% доступно только при выраженной
  высокочастотной составляющей D-term, достаточных данных, подтверждённой шкале,
  совпадении версий 4.3–4.5 и известных ручных настройках D-term. Это **не** рекомендация
  автора Betaflight и **не** доказанная оптимизация. Проверка — повторный полёт.
* Шкала, версия, неизвестные параметры и активные слайдеры не угадываются.
  Более новые версии можно декодировать, если их понимает включённый upstream,
  но численные кандидаты для них выключены.
* По глобальному RMS нельзя надёжно разделить P, D, feedforward, задержку и насыщение.
  Оптимальные PID автоматически не рассчитываются. Step-response идентификация,
  RPM-спектрограмма и статистическое сравнение двух полётов пока не реализованы.
* Плавность/резкость меняет цель и план проверки, а не измеренный спектр.
  Масса сама по себе не определяет коэффициенты PID.
